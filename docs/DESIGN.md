# MindFlow 視覺系統

本檔是視覺的**目標值**。文中不陣述現況 —— 現況一律由實作者 trace。

## 0. 一條硬規則

**容器尺寸由空間決定，不由內容決定。**（D8）SwiftUI 四個地雷：`Divider`、`ScrollView`、`ZStack`（依最大子項擐大）、`GeometryReader`（超大內容釘 topLeading）。無法用 grep 守門，review 時強制詢問。

## 1. 色彩

色票 A（owner 裁定），來源 colorhunt 最熱門。

| 用途 | 值 |
|---|---|
| 畫布底 | `F2EFE7` |
| 卡片底 | `FFFFFF` |
| 內文 | `2A2A28` |
| accent / 根節點 | `3368A0` |
| 次要面、塔色 | `C8DFDB` |
| 次要文字 | `5E6C6F` |

### 中性色也從 accent 色相推導

沒有任何中性色是手挑的：全部取**色相 211°、極低彩度**。用系統預設的中性灰會讓深色模式退化成泛用 App。

| 深色模式 | 值 | 對比度 |
|---|---|---|
| 畫布 | `101819` | — |
| 卡片 | `1B2628` | — |
| 內文 | `E2E9EB` | 14.65 / 12.62 |
| 次要文字 | `9AA7AA` | 7.27 |

深色分支色：同 h、同 C，**只升 L** 至達門檻。

分支色**必須推導，不得手挑**：OKLCh 固定 L/C、繞 h 六等分；超 gamut **只降 C**、不動 L。

```
3368A0  7A5291  984955  8A5A08  4E722C  067572
```
對比度 4.82–5.34。**均勻本身就是「一家人」的成因**；HSL 等 S/L 繞色相會讓對比度從 7.01 掉到 1.91，絕對不可用。

門檻：**承載內文 4.5:1；線條、邊框等非文字 3:1。**拿 4.5 卡線條會把色票遭暗、毀掉性格。

深色模式：同 h、同 C，**只拉高 L**。色相改了就不是同一套主題的深色版。

## 這份文件裡的數字

**只有被檢查強制的數字才寫在這裡；其餘一律指向程式碼。**

理由是實例：§2 與 §3 曾把字級、內距、圓角、最大寬拄在文件裡，程式早已改成別的值，**兩邊静默不一致了很多輪**，最後導致一份以舊值為前提、實際會造成退步的提案。

§8 的圖標幾何、對比門檻、重心容差沒漂，因為 **Checks 會失敗**。沒人守的數字就會爛。

## 2. 字體

SF Pro（系統）。層級靠**字重與尺寸**，不靠顏色 —— 顏色已經拿去表達分支。

**字級、字重、行數上限、最大文字寬的唯一來源是 `NodeStyle.of(depth:)`。**不在此重述。

設計契約（尚未被檢查強制，待補）：**相鄰層級的實渲染文字體高比 ≥ 1.10**，否則審別不出來。

## 3. 節點

- 圓角、內距、minSize、maxTextWidth：**以 `NodeStyle.of(depth:)` 為準**，不在此重述

### 三層形態（取代「全部都是邊框」）

| 層級 | 填充 | 文字 | 對比度 |
|---|---|---|---|
| 根 | 實心 `3368A0` | `F2EFE7` | 5.04 |
| 第一層 | 實心 = 所屬分支色 | `F2EFE7` | 4.82–5.34 |
| 第二層以下 | `FFFFFF` + 1.5pt 分支色邊框 | `2A2A28` | 12.52 |

原先寫「全部用邊框、層級靠字體」**是弱設計**：兩個相鄰層級只差一兩個字級時，層級會塌。實心與邊框的差異一眼分得出來，**不依賴字級差異能不能被審別**。

六個分支色配奶油字**全數 ≥ 4.82**，實心層安全。

## 4. 連接線

- 2pt 三次貝茲，控制點水平偏移 = 水平距離的 45%
- 色 = 分支色，不渐變
- **必須跟插入指示器形狀區隔**：連接線是細曲線，指示器是粗直線

## 5. 狀態

| 狀態 | 表現 |
|---|---|
| 選取 | 2pt accent 外圈，外推 2pt |
| 重掛目標 | 2.5pt accent 外圈，外推 3pt，**加 `C8DFDB` 20% 塔色** |
| 拖曳中子樹 | opacity 0.6，不加陰影、不放大 |
| 插入指示器 | 3pt 直線、圓角端點、accent、長度 = 目標兄弟寬度 |

選取與重掛目標**同時出現時必須分得出來**，塔色是區別子。

## 5.1 縮放行為

三類幾何量，規則不同。

| 類別 | 例子 | 縮放行為 |
|---|---|---|
| **狀態訊號** | 指示器線寬；選取 / 重掛 / search / batch / hover 的線寬與外推 padding；圓角加值；虛線 | **螢幕上尺寸恆定**（除以 scale）|
| **內容** | 卡片寬、字體、間距 | 隨版面縮 |
| **命中帶** | `SiblingInsertion.hint` 的啟動帶 | **隨內容縮 —— 刻意不固定** |

新增的狀態訊號自動適用第一條，不必逐項列清單。

### 命中帶為什麼不跟著固定

以 vGap=14pt、節點高 ~30pt 估，若帶寬固定為螢幕 12pt：

```
fit     間隙螢幕寬   相鄰間隙中心距   固定 12pt 帶
fit1.00       14.0          44.0        合理
0.618          8.7          27.2        已溢出間隙
0.50           7.0          22.0        已溢出間隙
0.25           3.5          11.0        溢出，且觸及相鄰間隙
```

**fit 低於約 0.86，固定帶就寬過整個間隙。**帶寬溢出後，畫面上每一點只剩兩種身分：在節點上（重掛）或在帶內（排序）—— **自由位移沒有立足之地**。而地圖越大、節點在螢幕上越密，侵蕃越嚴重。

自由畫布是 owner 明確提出的需求，不得為了「縮小時排序好叫」而換掉。

### 所以縮小時拖曳排序難命中，這是預期行為

**不要把它當 bug 修。**能力沒有遺失：`Alt+↑↓` 交換兄弟、`Alt+Cmd+↑↓` 移到首/末，兩者與縮放無關。

拖曳排序是放大時的手勢；鍵盤排序是全縮放級的。退化是安全的：看不到指示器 → 得到自由位移 → **不會發生静默的結構變更**。

## 6. 動態

- 指示器淡入 80ms；**消失不做動畫**（契約失效要立刻知道）
- 版面變化 160ms ease-out，**無回彈**
- 鍵盤連按時動畫不得累積延遲

## 7. 空狀態

新文件 = 一個根節點，**直接進編輯**。不放插畫、不放說明文字。

## 8. App Icon

現況：owner 評「很醜」。

- macOS 規範圓角矩形（1024 畫布，圖形區 **824×824 置中**）
- 底：垂直漸層 `3368A0` → **`003C71`**
  - 後者是推導值：同 h 251.8、**同 C 0.1059**、L 降至 0.3557（×0.70），此 L 下不需降彩度即在色域內
  - 曾手挑 `1E3F63`，實測彩度只有 0.0738（**低 30%**），與註解宣稱的「同 h/C」不符
  - 推導時若超色域，**只降 C**；不得直接裁切 RGB 通道 —— 裁切會造成色相漂移（實測 251.8→254.8）
- 字形：**一個中心節點 + 三條分支**
- **全部墨色（含三個末端圓點）用 `F2EFE7`**
  - 曾規定圓點用分支色 `7A5291`/`984955`/`4E722C`，**實測對漸層底的對比只有 1.15 / 1.31 / 1.65**，遠低於非文字 3.0 門檻 —— 16px 時會直接糊進背景
  - 奶油色同位置為 **6.12 / 7.00 / 8.02**。**規格錯、原型對**，以奶油色為準
  - 圖標在 16px 要的是最大對比，不是色盤忠實度
- **不放文字、不放燈泡、不放大腦**
- 程式化產生（CoreGraphics 畫 → `iconutil`），**圖標是程式碼，不是二進位資產**

### 字形分三個尺寸帶（已量測驗證）

小尺寸要的**不是同一張圖縮小，是自己的一張圖**。坐標以 1024 畫布撰寫：

| 尺寸帶 | 線寬 | 圓點 | hub 寬 | 分支展開 | 水平平移 t |
|---|---|---|---|---|---|
| ≥128px（large） | 40 | 104 | 210 | 230 | **−56.75** |
| 32–64px（mid） | 78 | 132 | 200 | 215 | **−82.50** |
| 16px（small） | 112 | 158 | 190 | 200 | **−101.75** |

t 套用於 hub、分支起點、控制點、端點（背景不動、形狀不改）。**三帶 t 不同是正常的** —— 共享的不變式是「重心居中」，t 只是達成它的手段，而三帶本來就是三張獨立重畫的圖。

t 由凍結的選值規則決定，不手挖：可行點中最小化 `max(|dx|/容差)`，依序以最大 weakest peak、最大 min endpoint contrast、最小 |t| 決勝，且 **t±1 也必須可行**（不取邊界點）。

實測餘裕：small .0789 / peak 693 / endpoint 5.976；mid .1083 / 712 / 6.030；large .0785 / 712 / 6.030。

### 字形幾何（1024 畫布，CoreGraphics 座標：y 向上為正）

以下為通過驗收的渲染所用值，**為正式規格**，不得另行猜測：

| 項目 | 值 |
|---|---|
| 圖形區（裁切路徑） | `x=100, y=100, w=824, h=824`，圓角半徑 **185** |
| 背景漸層 | 垂直，`y=1024` 處 `3368A0` → `y=0` 處 `003C71` |
| hub（中心節點） | `x=250, y=447, w=hub寬, h=130`，圓角半徑 **34** |
| 中線 | `mid = 512` |
| 三個端點圓心 | `(742, mid+展開)` `(766, mid)` `(742, mid-展開)` |
| 分支起點 | `(250 + hub寬, mid)` |
| 貝茲控制點 | `control1 = (600, mid)`，`control2 = (610, 端點 y)` |
| 端點圓點 | 以圓心為中心填滿，直徑 = 尺寸帶的「圓點」值 |
| 線尾 | `.round` |

掃描參數：取 **`x = floor(px × (0.70 + t/1024))`** 的垂直像素列（t = 該尺寸帶的平移量）；墨色判定為 **R+G+B > 470**。

**掃描欄釘在字形上，不釘在畫布上。**斷言的本意是「三條分支分得開且都實」，不是「畫布 70% 處有三段」。字形平移後若欄位不跟著走，量到的是字形的別的部位 —— 曾因此得到 peak 679 的假失敗。

公式在 t=0 時退化為舊定義 `floor(px × 0.70)`，**校準相等，因此這是座標系修正，不是門檻放寬**。

### 驗收（三條都要過，缺一不可）

掃描 x=70% 的垂直像素列：

1. **墨色區段數 恰為 3**（用 `== 3`，不是 `>= 3`；多出來的段是破圖，不是更好）
2. **最弱區段峰值 ≥ 680**（滿墨 712；背景實測 **173–315**，即 `003C71`–`3368A0` 的通道和）
3. **每個末端圓點對當地背景的對比 ≥ 3.0**
4. **墨色重心距底板中心，兩軸皆 ≤ max（1% 底板寬，1 裝置像素）**

第四條用重心而非 bbox：從中心向右輐射的構圖，**對齊 bbox 邊距反而會看起來偏右**。實測完成品邊距左 94 / 右 163，重心偏移 0.07%（修正前 6.78%）。

容差取 max 是因為不得要求比像素格教能表達的更好：≥128px 由 1% 綁定，≤64px 由 1 像素綁定。

第三條是必須的：**x=70% 的掃描線穿過的是分支線，不穿過圓點**。圓點即使畫成隱形，前兩條照樣 PASS —— 這個盲點差點讓分支色圓點的錯誤規格進入實作

第二條不可省。只測第一條時，線寬 34 在 16px 仍回報 3 段，但峰值只有 550 —— **技術上存在、視覺上虛掉**。

陰性對照：線寬 220 時區段數必須崩成 1。
