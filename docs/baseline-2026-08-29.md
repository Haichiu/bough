### U3 UUID 具體對照

```text
before N-0010 = 0000000a-0000-4000-8000-00000000000a
after  N-0010 = 0000000A-0000-4000-8000-00000000000A
canonical sorted(id,parent_id) = IDENTICAL
```

這是同一 UUID 的大小寫正規化，不是 ID churn。oracle 仍以 ID/parent ID 為鍵，只忽略 UUID 字母大小寫與 sibling 序列順序；不使用 text-based Counter。

## 作廢的舊數據

8/28–8/29 早期的 `0 pass / 5 fail`，以及修 harness 前的一次 `0 pass / 6 fail`，**不具產品判定效力**。污染來源同時有：

1. **搜尋 overlay 遮蔽**：`searchOverlay` 曾無條件渲染，且 HStack 內 Divider 高度無上限，毛玻璃面板覆蓋整個畫布；已由 `1988012` 修正。
2. **z-order / 全域輸入污染**：Ghostty/Safari/Helium 可位於 MindFlow 上方，global CGEvent/cliclick 會打到錯誤 app。背景 `CGEventPostToPid` 探針也無法驅動 SwiftUI 點擊。
3. **絕對座標濾鏡**：舊 `x>=1100` / `y>250` 在視窗幾何改變後誤判；已改視窗相對區域。
4. **harness bug**：`uit_report` PASS 少參數在 `set -u` 下崩潰；`uit_context_menu` / `uit_commit_field` 把回傳 stdout 丟到 `/dev/null`；舊 U4/U6 斷言也與最新 D2 相反。
5. **metadata bug**：舊 `run.sh` 在結束時讀當前 HEAD；並行文件 commit 會讓它冒充受測 App commit。已改由 `UITEST_COMMIT` 注入並輸出 binary SHA16。

因此，不能再把舊 0-pass 主要歸因於「幾何漂移」；overlay 遮蔽與錯誤的 global-input target 更根本。

## Harness 安全與限制

- 所有 global input（cliclick、CGEvent、System Events keystroke/key code）送出前都驗證 frontmost 是 `MindFlow`；否則 exit 70，整套立即中止並 restore，避免誤操作 owner 的 Ghostty/Safari/Helium。
- `run.sh` 區分 PASS / FAIL / SKIP；exit 77 是環境無法驗證，不是產品 FAIL。
- `uit_pin_geom` 已刪除：實測 `defaults write` 成功但 App 忽略 frame，且會修改 owner preferences。視窗相對 AX filter 已足夠。
- Tab 無法由已試過的合成路徑穩定遞送；右鍵／menubar add-child 僅驗同一 ViewModel 路徑，不冒充實體 Tab 鍵驗證。
- Esc 在本輪 U4 合成測試成功走完 discard；owner 亦人工確認。特殊鍵仍可能受 macOS 合成事件環境影響。
- U5 UI latency **未完成**；性能保障交給可重現的 headless benchmark，而非 AX polling。
