# MindFlow 路線圖

> 最後更新：v21.1（第 219 批）。本文件記錄尚未實作的候選功能、設計考量與風險評估，供未來迭代決策參考。

## 候選大項（皆需先做設計決策）

### 1. 概要括線（Summary Brackets）
- **價值**：XMind 的招牌功能之一，框選一組兄弟主題加註摘要。
- **設計待決**：沒有多選的情況下，如何指定括線範圍？候選方案：
  - 右鍵「與下一個兄弟合組概要」（只支援相鄰對）
  - 先做多選再做概要（依賴項目 2）
- **工程範圍**：資料模型（MindDocument.summaries）＋四種版面的空間預算＋畫布/SVG 渲染＋互動。
- **風險**：版面引擎是全專案最精密的部分，任何改動都需完整回歸測試。預估 2–3 個批次。

### 2. 多選（Multi-Select）
- **價值**：批次上色／標星／刪除；也是概要括線的前置。
- **設計待決**：`selection: UUID?` → `Set<UUID>` 的遷移波及約 50 處呼叫點；Shift-click 與拖曳框選的手勢如何與既有手勢並存。
- **風險**：架構級重構，建議拆成「資料層遷移」→「Shift-click」→「框選」三步。

### 3. 圖片附件（Image Attachments）
- **價值**：視覺型使用者的強需求。
- **設計待決**：
  - 儲存：內嵌 base64（單檔可攜但肥大）vs 外部資料夾（瘦但破壞單檔性）
  - 版面：節點高度需隨圖片變化，四種版面都要處理
- **風險**：儲存格式是不可逆決策，影響 .mindmap 相容性承諾（見 FORMAT.md）。建議先做使用者調查再動工。

## 已知限制（非缺陷）

- SVG 匯出以淺色為基準，不跟隨系統外觀（保證跨平台一致性）
- 魚骨圖匯出 SVG 時連接線以通用貝茲曲線呈現（與畫面的魚骨專屬畫法略有差異）
- 簡報模式下拖放文字仍可編輯內容（屬刻意保留的輸入通道；⌘Z 歷史已隔離）
